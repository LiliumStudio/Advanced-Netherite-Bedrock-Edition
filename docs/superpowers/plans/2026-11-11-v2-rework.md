# Advanced Netherite V2.0.0 Rework Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reescribir el addon en TypeScript sobre `@minecraft/server` 2.11.0, con paridad de comportamiento con 1.4.0, mejor rendimiento y migración completa de mundos 1.4.x.

**Architecture:** Hay tres capas. `core/` es lógica pura, sin imports de `@minecraft/*`, y se testea con Vitest. `platform/` envuelve el API: scheduler, storage y eventos. `features/` conecta core y platform, un archivo por sistema. Una sola tabla de materiales en `core/materials.ts` alimenta protecciones, drops y lore.

**Tech Stack:** TypeScript 5.9, dash compiler (plugin `typeScript`), Vitest, `@minecraft/server` 2.11.0, `@minecraft/server-ui` 2.3.0, `@minecraft/vanilla-data` 1.26.60.

**Spec:** `docs/superpowers/specs/2026-11-11-v2-rework-design.md`

## Global Constraints

- `@minecraft/server` = `2.11.0`, `@minecraft/server-ui` = `2.3.0` (manifiesto y `package.json`, versiones exactas).
- `min_engine_version` = `[1, 26, 60]`; versión de header/módulos = `[2, 0, 0]`; nombre `"Advanced Netherite BP - V2.0.0"` / `"... RP - V2.0.0"`.
- UUIDs de manifiesto e IDs de items/bloques: **sin cambios**.
- Ningún archivo bajo `BP/scripts/core/` importa `@minecraft/*`.
- Imports relativos en TS con extensión `.js` (`import { x } from "./x.js"`); compila igual en dash, tsc y Vitest.
- Nombres de tags de jugador `lsan:phantom_immune`, `lsan:piglin_immune`, `lsan:enderman_immune`: sin cambios (los usan `BP/entities/*.json`).
- Claves de traducción existentes (`tooltip.lsan:*`, `config.lsan:*`, `lsan.welcome.*`): sin cambios.
- Commits sin atribución a Claude (preferencia del autor).
- Rama de trabajo: `rework/v2`.

## Review Focus

1. **Payload de la barra de armadura distinto en un byte** → la UI del RP (`hud.uids`) deja de mostrar la barra. Se espera un payload idéntico al de 1.4.0 para el mismo equipo. Lo cubre el test `encodePayload matches v1 golden` (Task 4).
2. **Mundo 1.4.x con config corrupta o con claves fuera de rango** (por ejemplo `"additionalWheatDropChance": 5` o un JSON inválido) → se esperan los defaults en las claves inválidas, sin crash y conservando las válidas. Lo cubre el test `migrateWorld sanitizes invalid values` (Task 2).
3. **Ejecutar la migración dos veces**, por ejemplo al recargar el mundo o al reconectarse → no debe cambiar nada la segunda vez. Lo cubre el test `migrations are idempotent` (Task 2).
4. **Un jugador que entra en creativo y después pasa a supervivencia** → la barra debe aparecer sin cambiar de equipo. Lo cubre el test `ArmorBarState forgets payload when hidden` (Task 4).
5. **Netherite vanilla en la mano secundaria o con lore y nombre propios** → se convierte y conserva nombre, encantamientos, daño, lore y dynamic properties. Lo cubre el test `planConversion keeps metadata` (Task 5) más el checklist manual de la Task 9.
